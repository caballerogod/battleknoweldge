# «Своя игра»: правила, подключение модели и проверка

При открытии сайта пользователь выбирает «Своя игра» или «Битва знаний». Профиль общий. Счёт «Своей игры» хранится отдельно от XP и адаптивной аналитики «Битвы знаний». Второй режим не меняет прежний банк и правила первой игры.

## Что работает без API-ключа

Кнопка «Попробовать демо с готовыми темами» запускает настоящую локальную партию на 25 вопросов. Пять фиксированных тем: программирование, математика, история, география и наука. Поле, выбор, таймер, проверка, счёт, сохранение и итоги работают с реальным backend/SQLite. Это не генерация ИИ. Надпись «Демонстрационная партия · готовые вопросы» видна на игровом экране.

В деморежиме принимаются эталонные ответы и подготовленные варианты, включая произнесённые числа, «аш два о», «два знака равно», синонимы известных терминов. Произвольная смысловая оценка без модели недоступна. Пользователь видит распознанный текст, может исправить его и только затем подтвердить. Корректность реальной генерации GPT и реального смыслового оценивания нельзя считать проверенной по этим демовопросам.

## Подключение настоящей генерации

1. Создайте OpenAI API-ключ в своём аккаунте API с доступом к модели и доступным балансом. Подписка ChatGPT сама по себе не используется приложением как ключ.
2. Скопируйте `backend/.env.example` в `backend/.env`, если файла ещё нет.
3. В backend/.env задайте OPENAI_API_KEY своим значением и роли OPENAI_GENERATION_MODEL=gpt-5.4, OPENAI_REVIEW_MODEL=gpt-5.4, OPENAI_GRADING_MODEL=gpt-5.4-mini. Ключ не отправляйте в чат и не помещайте во frontend.
4. Обновите страницу и снова откройте «Своя игра»: доступность сервиса считывается с сервера. Настройки `.env` читаются при обращении, перезапуск для изменения ключа не обязателен. Переменные окружения процесса имеют приоритет над файлом.
5. Введите пять разных тем и нажмите «Подготовить вопросы». Появится этап подготовки. После успешного ответа модели откроется поле. При ошибке сети, лимита или некорректном ответе модели игра показывает ошибку, а не подставляет демовопросы.

Используется серверный Responses API с JSON Schema (Structured Outputs), GPT-5.4 для генерации и редактуры, GPT-5.4 mini для проверки ответов, store:false. Один запрос готовит весь комплект из 25 вопросов. Далее запросы смысловой проверки нужны только для ответов, не совпавших с эталоном/алиасами. Генерация и оценивание оплачиваются аккаунтом владельца ключа. Точную стоимость следует оценить по фактическому usage после подключения, а не обещать заранее.

Документация: https://developers.openai.com/api/docs/models/gpt-5.4-mini и https://developers.openai.com/api/docs/guides/structured-outputs . Формат JSON не гарантирует фактическую истинность вопросов: на живой модели ещё предстоит проверить качество разных тем, сложность и справедливость проверки. Вопросы с неопределённым вердиктом снимаются без штрафа. Автоматическое тестирование адаптера с подменённым HTTP-ответом не является реальным вызовом OpenAI.

## Как играть

- Назовите тему и стоимость: «Наука за сто», «История за триста», «третья тема за двести». Или выберите клетку мышью.
- Жестами: 1–5 пальцев выбирают тему; затем 1–5 пальцев — стоимость 100–500. Удерживайте позу 0,8 с. Для одинакового числа на обоих шагах уберите руку на 0,3 с. Новая поза может выбрать следующий шаг. Большой палец вверх подтверждает клетку. Подсчёт пальцев использует геометрию реальных landmarks MediaPipe; уверенность классификатора 👍 проверяется отдельно.
- Клетка только подсвечивается до подтверждения. Скажите «Подтвердить»/«Открыть вопрос», нажмите кнопку или покажите 👍.
- После открытия запускается серверный таймер 30 секунд. Вопрос озвучивается браузером при включённом звуке; чтение входит в эти 30 секунд. Во время озвучки распознавание временно приостанавливается.
- Произнесите сам ответ одной фразой. Текст появляется в поле «Ваш ответ». Можно исправить его клавиатурой или сказать «исправить ответ», затем повторить. Скажите отдельной командой «Подтвердить» или покажите 👍. Фраза не отправляется на проверку автоматически.
- Верный ответ даёт стоимость клетки, неверный отнимает её. Пропуск, истечение времени и снятый неоднозначный вопрос дают 0 очков. «Пропустить» — явная команда без штрафа.
- После результата: «дальше» или кнопка возвращают к полю. Последний вопрос сначала раскрывает результат и объяснение, затем открываются итоги. Сыгранные клетки повторно недоступны.
- «Выбор игры» возвращает к двум режимам и освобождает устройства. Партия остаётся доступна через «Продолжить партию». Дедлайн уже открытого вопроса продолжает идти. «Завершить партию» на поле сохраняет итог досрочно.

Голос использует Web Speech API браузера, не аудиовход GPT-5.4 mini. Для реального голосового теста используйте обычный Chrome/Edge с доступом к микрофону. Распознавание может обращаться к сетевому сервису браузера; видео анализируется локально. Физические устройства и акустика требуют проверки на компьютере пользователя.

## Данные и устойчивость

Новая таблица `trivia_games` добавляется без удаления прежних игроков, сессий и ответов. Полный комплект с эталонами хранится только на сервере; до выбора клеток браузеру доступны лишь темы, цены и состояние. Текст открытого вопроса доступен до ответа; эталон и объяснение — после завершения этого вопроса.

Создание партии имеет идентификатор запроса: повторная отправка не создаёт вторую генерацию. Принятый свободный ответ фиксируется до обращения к оценщику, его нельзя заменить при повторной проверке. Сетевая ошибка проверки не вызывает штрафа; можно повторить проверку того же текста после истечения исходного дедлайна. Проверка не удерживает SQLite write lock на время обращения к модели.

Генерация и проверка выполняются серверными BackgroundTasks. Партия и ответы сохраняются в SQLite. После перезапуска сервера незавершённая генерация честно помечается прерванной; зафиксированный ответ сохраняется и его проверку можно повторить. Это локальное приложение; распределённая очередь заданий и публичная авторизация в эту итерацию не добавлены.

`.env` исключён из Git и архива проекта. В архив входит только пустой `.env.example`. Новый код использует уже имеющиеся httpx/Pydantic/SQLAlchemy; npm-зависимости не добавлены. Модель камеры продолжает загружаться только при включении камеры.

## Редактура вопросов, 23 октября 2026
Генерация использует общую шкалу 100–500 относительно взрослого любителя темы и примеры удачных/неудачных вопросов. Даже 100 требует знания внутри темы. Для 500 запрещено подменять сложность случайными датами, редкими фамилиями и статистикой. Для мемов по умолчанию ориентир — русскоязычная аудитория и международная классика; поиск источников не подключён, поэтому популярность и факты не гарантированы.

После генерации отдельный запрос редактора проверяет весь ряд, цены, ответы, банальности, неоднозначность и тематичность. Локальный фильтр дополнительно блокирует совпадение ответа с темой и полный текстовый ответ в вопросе. Один запрос исправляет замечания, затем весь комплект проверяется повторно. Если замечания остаются, партия получает понятную ошибку вместо слабого поля. Максимум четыре API-запроса на подготовку; при хорошем первом комплекте два. Время подготовки и расход API увеличиваются. Существующие партии и демобанк не изменяются. Проверка моделью не заменяет внешнюю проверку фактов.

Автоматически проверены замена и повторная редактура, ограничение числа попыток, отказ при плохом результате и при обходе локального фильтра. 50 backend-тестов пройдены.

## «Своя игра» на троих — актуальный формат, 23 октября 2026

Вход: имя первого игрока для сохранения локальной партии; на экране подготовки — три разных имени и восемь общих тем. Получается 40 клеток: восемь рядов по 100–500. Один компьютер и общий экран. Играют по очереди: после верного, неверного, пропущенного, снятого вопроса или таймаута отвечает следующий участник. Очки начисляются только отвечавшему: +цена за верный, −цена за неверный, 0 за пропуск/таймаут/неопределённость. Это локальная партия, подключения с трёх устройств и гонка на кнопку не реализованы.

Сервер хранит имена; счёт вычисляется из сохранённых результатов с номером участника. При открытии клетки сервер фиксирует отвечающего и дедлайн 30 секунд; обновление не меняет ни одно из этих значений. Результаты и повторная отправка ответа не дублируют очки. Итоги показывают всех троих, сортируя по очкам; равные результаты остаются равными.

Форматы: свободный ответ, загадка, четыре варианта, вопрос с иллюстрацией. Сервер случайно перемешивает форматы по ценам ещё до генерации; модель получает обязательный план. В каждой теме есть свободные вопросы, загадка и варианты. Картинка назначается только теме, подходящей к локальному каталогу; если подходящей иллюстрации нет, добавляется вопрос с вариантами. Поэтому изображения доступны не для каждой произвольной темы.

В этой версии каталог — восемь собственных SVG-иллюстраций: флаги Японии и Бразилии, треугольник, схема затмения, шахматная доска, баскетбольная площадка, оригинальная отсылка к мему и последовательность кадров. Это схемы/рисунки, не поиск фотографий и не генерация оригинальных мемов. Чужие URL, HTML и SVG из ответов модели не принимаются. Демо использует отдельный готовый набор 40 вопросов; цены в демо не проходят ИИ-редактуру и служат проверке механики.

Голос: названия тем, «шестая», «седьмая», «восьмая тема за двести»; в вариантах — «первый»…«четвёртый», затем «подтвердить». Жесты: 1–5 пальцев выбирают тему в текущей группе, затем стоимость. Кулак переключает группы 1–5 и 6–8. Для второй группы 1/2/3 пальца означают темы 6/7/8. В вопросе с вариантами 1–4 пальца выбирают вариант. Большой палец подтверждает; удержание одной позы не повторяет действие без отпускания. Смена группы доступна также кнопками и фразой «другая группа». Текущий участник подсвечен.

Старые одиночные партии на пять тем остаются доступными для продолжения; новые создаются на троих. SQLite обновляется добавлением колонки participants, без удаления данных. Новые поля расширяют прежний API. Токен и ожидание генерации увеличены для 40 вопросов; генерация по-прежнему идёт в фоне и включает редактуру.
Простые картинки из текущего каталога назначаются случайно только за 100–300 очков; более дорогие клетки используют другие форматы.

## Разделение моделей и расходы API — 23 октября 2026
Актуальные настройки backend/.env:
OPENAI_GENERATION_MODEL=gpt-5.4
OPENAI_REVIEW_MODEL=gpt-5.4
OPENAI_GRADING_MODEL=gpt-5.4-mini

Существующий OPENAI_API_KEY используется сервером для всех трёх ролей. Общая настройка OPENAI_MODEL больше не выбирает модель; удалите её при переходе на отдельные роли. Генерация и исправление используют GENERATION, выпускающая проверка — REVIEW, смысловая проверка свободного ответа — GRADING. Точные ответы и варианты по-прежнему проверяются локально без запроса модели.

Журнал backend/ai_usage.db хранит только технические метаданные: UUID попытки/партии, этап, запрошенную и фактически указанную в ответе модель, статус, HTTP-код, response ID, длительность, входные/кэшированные/выходные/рассуждающие токены и оценку USD. Тексты вопросов, ответы игроков и API-ключ в журнал не записываются. Перед отправкой создаётся запись попытки; если журнал недоступен, платный запрос не отправляется. Прерванный запрос или ответ без usage виден как запрос без оценки, а не как гарантированно бесплатный.

Стоимость сохраняется и для incomplete, некорректного JSON и ошибок с usage. Повторные редакторские запросы учитываются отдельно. reasoning_tokens уже входят в output_tokens и повторно не прибавляются. Кэшированная часть входа считается по отдельной ставке. Для GPT-5.4 учтён повышенный тариф при входе более 272000 токенов. Используется service_tier=default; неизвестная модель/тариф или отсутствие usage помечаются без оценки.

На экране настройки — общий учтённый расход сервера, в партии (включая подготовку, ошибку и итоги) — расход этой партии. GET /api/trivia/usage возвращает суммарные данные и разбивку по модели/этапу. GET /api/trivia/config содержит публичные названия моделей и суммарные расходы, без ключа. Счётчик ведётся с этого обновления, не восстанавливает прошлые расходы и не читает баланс аккаунта OpenAI.

Оценка использует тарифы, проверенные 23 октября 2026, USD за 1 млн токенов:
- gpt-5.4: вход 2.50, кэш 0.25, выход 15.00.
- gpt-5.4-mini: вход 0.75, кэш 0.075, выход 4.50.
При изменении цен таблицу нужно обновить; сохранённая стоимость прежних запросов не пересчитывается. Это оценка по usage, не платёжная выписка, остаток $50 или гарантированный лимит расходов.

Источники: https://developers.openai.com/api/docs/models/gpt-5.4 , https://developers.openai.com/api/docs/models/gpt-5.4-mini , https://developers.openai.com/api/docs/guides/token-counting .
Журнал исключён из Git и ZIP как файл .db. Для изолированной проверки можно задать AI_USAGE_DB; новые зависимости не нужны.
Для полного поля GPT-5.4 использует low reasoning и таймаут 300 секунд; отдельный редактор — low / 120 секунд, mini для проверки ответа — low / 40 секунд. Это уменьшает задержку большого JSON, сохраняя отдельную проверку качества.


## Бесплатная локальная модель (Ollama)

Для «Своей игры» добавлен независимый локальный режим: Qwen3 4B Instruct создаёт вопросы, выполняет редактуру и проверяет свободные ответы. OpenAI API не вызывается; ключ не требуется. Точные совпадения и варианты ответа по-прежнему проверяются сразу на сервере.

В `backend/.env`:
```
AI_PROVIDER=ollama
OLLAMA_MODEL=qwen3:4b-instruct
```

На этом компьютере Ollama установлена отдельно от проекта в `%LOCALAPPDATA%/Programs/AIKnowledgeBattle-Ollama`, веса — в `%USERPROFILE%/.ollama/models`. На другом компьютере сначала установите [Ollama для Windows](https://ollama.com/download/windows). Затем запустите `Start-Local-AI.ps1`; он запустит локальный сервис и при необходимости загрузит модель. Загрузка весов — около 2,5 ГБ. `Start-Backend.ps1` также запускает этот помощник при `AI_PROVIDER=ollama`. После этого запустите frontend обычным способом.

Модель работает на процессоре; 16 ГБ RAM подходит для выбранного варианта, но свободная память и другие программы влияют на скорость. Подготовка 40 вопросов может занять заметное время: экран показывает тему и этап редактуры. Вопросы создаются пакетами по пять, каждый пакет проходит редакторскую проверку и до двух исправлений; принятые темы не генерируются повторно в этой попытке. Не прошедшая проверку тема сообщает об ошибке, демо не подставляется вместо генерации.

Локальная модель слабее больших облачных моделей: возможны фактические ошибки, особенно в узких темах и мемах. Фильтры не гарантируют достоверность каждого факта. Это рабочий бесплатный режим для разработки и пробных партий, а не обещание качества GPT-5.4.

Все обращения адаптера идут только на `127.0.0.1:11434`, без прокси окружения. Автоматического перехода на OpenAI нет. Облачные теги Ollama запрещены; запускаемый проектом сервис получает `OLLAMA_NO_CLOUD=1`. Отсутствие сервиса/модели явно отображается на экране тем.

Журнал сохраняет локальные вызовы с префиксом `ollama/`, токены и нулевую стоимость API, включая неудачные попытки. Старые расходы OpenAI остаются в истории. Это учёт API, а не баланс аккаунта и не стоимость электричества. Веса, runtime, `.env` и базы данных не входят в ZIP проекта.

Для осознанного возврата к OpenAI нужно вручную изменить `AI_PROVIDER=openai`, настроить ключ и перезапустить backend; платные модели сохраняются в настройках отдельно.

Документация: [структурированный JSON Ollama](https://docs.ollama.com/capabilities/structured-outputs), [Qwen3 4B Instruct](https://ollama.com/library/qwen3:4b-instruct).


## Текущий основной режим: OpenAI

По запросу пользователя основной провайдер возвращён на `AI_PROVIDER=openai`: GPT-5.4 для генерации и редакторской проверки, GPT-5.4-mini для смысловой проверки свободных ответов. Ollama остановлена; запуск backend в этом режиме не включает локальную модель. Ключ остаётся только в `backend/.env`.

Для партий на восемь тем редактор больше не переписывает все 40 вопросов при замечаниях. Сервер сохраняет одобренные клетки, запрашивает только отклонённые и отдельно проверяет замены. Допускается до трёх адресных исправлений; неполные замены, неизвестные клетки, несовпадение заданных форматов и окончательный отказ редактора останавливают подготовку. Демо не подменяет результат AI. Прежняя совместимость с одиночными партиями на пять тем сохранена.

Сгенерированная партия хранится в локальной базе; после обновления страницы её можно продолжить через «Своя игра» → «Продолжить партию». До открытия вопроса таймер не идёт. Камера, голос, отдельные очки трёх участников и таймер 30 секунд сохранены. При переносе проекта ZIP не содержит базу с подготовленной партией, ключ и журнал расходов: они остаются на текущем компьютере.
