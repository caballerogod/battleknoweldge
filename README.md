# AI Knowledge Battle — AI Битва знаний

На стартовом экране теперь **две игры**: «Битва знаний» и **«Своя игра»**. В «Своей игре» — пять тем, поле 25 вопросов стоимостью 100–500, голосовой/жестовый выбор клетки и свободный ответ с подтверждением. Настоящая генерация и смысловая проверка подготовлены для `gpt-5.4-mini` через серверный OpenAI API. **Без ключа доступна явно обозначенная демонстрация с готовыми темами**, а генерация своих тем отключена. Подключение, правила и ограничения: [docs/SVOYA_IGRA_RU.md](docs/SVOYA_IGRA_RU.md). Для ключа предусмотрен `backend/.env.example`; настоящие `.env` не входят в архив.

Локальная образовательная игра для университетского проекта: React + Vite + TypeScript, FastAPI, SQLAlchemy и SQLite. 90 вопросов на русском, адаптивные раунды по 10 вопросов, XP, уровни, достижения, аналитика, реальное распознавание жестов MediaPipe и голосовые команды Web Speech API. Платные API, Docker и облачная база не требуются.

Игровой экран оформлен как интеллектуальное шоу: отдельная сцена с круговым таймером, выбором ответа, фиксацией, короткой паузой и раскрытием результата. Итоги используют ту же студию. Камера и голос расположены в компактной панели, подробные настройки сворачиваются. Доступны клавиши **1–4** и **Enter**. Правила постановки, дизайн-концепты, адаптация и проверка описаны в [docs/SHOW_DESIGN_RU.md](docs/SHOW_DESIGN_RU.md). Таймер остаётся серверным и равен 30 секундам; анимации отключаются системной настройкой уменьшения движения.

## Установка на Windows 10/11

1. Установите **Python 3.11 или новее** с [python.org](https://www.python.org/downloads/windows/). В установщике включите Python Launcher и «Add Python to PATH».
2. Установите **Node.js 22.12+ (рекомендуется Node.js 24 LTS)** с [nodejs.org](https://nodejs.org/). Перезапустите VS Code после установки.
3. Откройте эту папку через File → Open Folder в VS Code. Terminal → New Terminal → PowerShell.
4. Проверьте `py -3 --version` и `node --version`.

Автоматическая установка из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\Setup.ps1
```

Или выполните вручную:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
cd frontend
npm.cmd ci
cd ..
```

Активация окружения не обязательна: инструкции вызывают его Python напрямую. Если хотите активировать: `.\.venv\Scripts\Activate.ps1`.

`npm ci` копирует WASM из установленной версии `@mediapipe/tasks-vision` и при необходимости скачивает официальную модель Google. Готовые модель и WASM уже включены в поставку. Для повторной подготовки: `cd frontend; node scripts/setup-mediapipe.mjs`.

## Запуск

В первом терминале из корня проекта:

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из корня проекта:

```powershell
cd frontend
npm.cmd run dev
```

Или запустите `Start-Backend.ps1` и `Start-Frontend.ps1` в двух терминалах. Откройте **http://127.0.0.1:5173** в Chrome или Edge. API-документация: http://127.0.0.1:8000/docs. Остановка серверов — Ctrl+C в каждом терминале.

Введите никнейм → «Войти в арену» → «Начать игру». Для каждого вопроса выберите ответ и подтвердите его. После объяснения нажмите «Следующий вопрос». Камера и голос — дополнительные способы выполнения этих же действий.

База `backend/battle.db` создаётся и заполняется автоматически. Не удаляйте её, если хотите сохранить прогресс. Для резервной копии остановите backend и скопируйте этот файл. Никнейм чувствителен к регистру; пробелы по краям удаляются. После обновления страницы нажмите «Продолжить игру»: уже выданный неотвеченный вопрос останется тем же. После подтверждённого ответа продолжение выдаёт следующий вопрос; объяснение предыдущего доступно в истории профиля. XP сохраняется сразу, в том числе при досрочном завершении раунда.

## Камера и жесты

В игровом экране нажмите «Включить камеру», разрешите доступ в браузере. Подождите загрузки модели. Держите одну руку в кадре при хорошем освещении.

| Жест MediaPipe | Действие |
| --- | --- |
| Pointing_Up — указательный палец вверх | A |
| Victory — два пальца V | B |
| Closed_Fist — кулак | C |
| Open_Palm — ладонь | D |
| Thumb_Up — большой палец вверх | Подтвердить выбранный ответ |

Для выбора A–D порог уверенности по умолчанию 65%; доступен выбор 55% / 65% / 75%. Удержание — 650 мс накопленных уверенных кадров. Короткая потеря классификации до 250 мс сохраняет накопленный прогресс, но не добавляет время удержания. Более долгая потеря, другая категория жеста или большой разрыв между кадрами сбрасывают удержание. Подтверждение 👍 требует 750 мс и порога `max(60%, выбранная чувствительность)`: 60% / 65% / 75%. Даже отдельные уверенные кадры, разделённые короткими провалами уверенности, накапливают удержание. Интервал между действиями — 1200 мс. Непрерывно удерживаемый жест выполняется один раз: уберите руку или смените жест для повторения. 👍 без выбранного ответа ничего не подтверждает. После ответа выбор блокируется. Для следующего вопроса используйте кнопку или голос. На видео отображаются реальные точки руки и шкала удержания. Кадр показывается целиком, без обрезания кисти. Выключение камеры и уход с игрового экрана освобождают видеопоток и модель. Видео не отправляется на backend.

## Голос

Для голоса используйте обычный Chrome или Edge: встроенный браузер может предоставлять микрофон, но не подключаться к речевому сервису. Нажмите «Включить микрофон» и разрешите доступ. Сначала появится «Подключаю речевой сервис…», а после реального события запуска — «Слушаю. Скажите одну команду и сделайте паузу». Используется `ru-RU`. Кнопка «Отменить запуск» позволяет отменить ожидание. Если сервис не запускается за 8 секунд, показывается отдельная ошибка.

Кнопка **«Проверить микрофон · 7 с»** проверяет локальный звуковой сигнал независимо от речевого сервиса. Показываются имя устройства, шкала уровня и результат. Проверка ничего не записывает и не отправляет. Если шкала реагирует на голос, но команды не распознаются, проверьте сообщение об ошибке речевого сервиса, интернет и используйте обычный браузер. Если шкала не реагирует, проверьте устройство ввода и громкость в Windows. Проверка и распознавание не захватывают микрофон одновременно: запуск одного режима останавливает другой.

- «Первый», «второй», «третий», «четвёртый» — A, B, C, D.
- Числовая запись распознавателя `1`, `2`, `3`, `4`, `1-й`…`4-й`, «ответ 1», «вариант 2» также выбирает A–D. Фразы с несколькими числами и посторонним текстом не выбирают ответ.
- «Ответ А», «ответ Б», «ответ В», «ответ Г» — A, B, C, D; поддерживаются также «вариант …» и ряд вариантов произношения.
- «Подтвердить» — отправить выбранный ответ.
- «Следующий» — продолжить после полученного объяснения.
- «Повторить вопрос» — подсветить вопрос и озвучить вопрос с вариантами средствами браузера.

Неизвестные и неоднозначные фразы игнорируются. Предварительный текст показывается, но действие выполняется только для финального результата. Распознавание запускается на одну фразу и контролируемо перезапускается; после трёх попыток без распознанной речи выводится совет проверить микрофон. Отмена и выход из игры исключают поздние события и повторный запуск. Озвучивание зависит от системных голосов; команды во время синтеза речи игнорируются. Речь может обрабатываться сетевым сервисом браузера: интернет и доступность сервиса зависят от браузера, региона и его настроек. При ошибке голос отключается с сообщением, а игра остаётся доступной мышью и жестами.

## Озвучка игры

В `frontend/public/audio/` включены **короткие фрагменты записи «Кто хочет стать миллионером?» от 18 ноября 2007 года**, извлечённые из [ролика пользователя](https://www.youtube.com/watch?v=Yzhau6No0KY): заставка, циклический фон ожидания, фиксация ответа, верный и неверный ответ, отсчёт. Предыдущие синтезированные сигналы заменены. Для истечения 30 секунд используется укороченный сигнал проигрыша; это назначение нашей игры, а не оригинальный таймер каждого вопроса телепередачи. Дополнительный сигнал крупного верного ответа сохранён для сравнения, но не включён в игровой сценарий.

Прослушать все восемь фрагментов с таймкодами можно на `/audio-preview.html` или по ссылке «Прослушать сигналы» в панели управления. Происхождение и границы каждого фрагмента записаны в `public/audio/sources.json`, разбор игровых событий выпуска — в `docs/AUDIO_REFERENCE_RU.md`. Скрипт `scripts/extract-reference-audio.py` воспроизводит нарезку из локального исходного аудио через FFmpeg. Фрагменты уже включены: для запуска игры YouTube, FFmpeg и распознавание речи на Python не нужны. Это запись эфира, не студийные мастер-файлы: возможны шум записи и зал. Голосовые объявления приложения по-прежнему произносит браузер, голос ведущего не клонируется. Права на аудио передачи не передаются проекту.

Старый `scripts/generate-audio.py` оставлен как запасной синтезатор; теперь он пишет только в отдельную папку `audio/synthesized-fallback/`, чтобы не перезаписать фрагменты передачи.

В панели управления по умолчанию включены голосовые уведомления:

- «Камера включена» — когда видео и модель жестов успешно готовы.
- «Микрофон включён» — когда речевой сервис действительно начал работу, один раз за ручное включение. Повторные подключения после фраз не повторяют уведомление.
- «Ответ верный!» / «Ответ неверный» — после проверки ответа сервером, включая восстановление сохранённого ответа при потере сетевого ответа.
- «Время вышло» — после серверного сохранения пропущенного вопроса.

Перед результатом выдерживается короткая пауза и звучит музыкальный сигнал, затем голос произносит результат немного медленнее и ниже. Голос использует синтез речи браузера `ru-RU`; при наличии предпочтителен локальный голос. Тембр и доступность голоса зависят от браузера/Windows. Музыкальные сигналы из WAV не зависят от наличия синтеза речи. API-ключи не нужны. Кнопка **«Звук игры: включён / выключен»** управляет и музыкой, и голосом; настройка сохраняется в браузере.

Во время речи игры распознавание команд приостанавливается: текущий recognizer закрывается, а его отложенные результаты игнорируются. После окончания озвучки и короткой паузы для затухания звука прослушивание возобновляется, если пользователь не отключил микрофон. Не произносите команды, пока показано «Игра говорит». При ошибке включения устройства ложное сообщение о его включении не произносится. При выходе из игры озвучка отменяется. Текст вопроса по команде «повторить вопрос» использует ту же очередь и защиту от эха; при отключённой озвучке вопрос только подсвечивается.

Пока микрофон включён или проверяется его уровень, фоновая музыка и тихие щелчки/тики не воспроизводятся. Это позволяет голосовым командам работать без помех; сигналы результата воспроизводятся с приостановкой распознавания. При управлении мышью и жестами доступен весь фон и отсчёт. Музыка останавливается после ответа, на нуле таймера и при уходе с игрового экрана.

При отсутствии синтеза речи или ошибке воспроизведения выводится сообщение; игра продолжает работать без звука. Если голос не слышен, проверьте звук вкладки, системную громкость и наличие русского голоса. Справка API: [MDN SpeechSynthesisUtterance](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance).

## Таймер: 30 секунд на каждый вопрос

Сервер назначает вопросу абсолютный дедлайн и сохраняет его в SQLite. Интерфейс показывает оставшееся время и выделяет последние 10 секунд. Обновление страницы, возврат в раунд и перезапуск backend не дают новые 30 секунд. Сервер проверяет время сам: даже правильный вариант, поступивший после дедлайна, считается пропуском.

На нуле интерфейс автоматически отправляет пропуск, без выбранного варианта и без XP. Серия правильных ответов обнуляется, вопрос учитывается как неверный, в истории отображается «Время вышло». Выбранный, но не подтверждённый до дедлайна ответ также считается пропущенным. Затем можно посмотреть объяснение и перейти к следующему вопросу с новым таймером. Если вкладка была закрыта или сеть пропала, сервер сохраняет пропуск при следующем запросе ответа/возврате в игру или завершении просроченного раунда. Повторные запросы не создают двойных ответов.

Таймер не останавливается на время озвучки, работы камеры, потери фокуса или ошибки сети. Если сохранение пропуска не удалось, интерфейс повторяет запрос; серверная проверка дедлайна остаётся в силе. Ранее созданная база обновляется автоматически добавлением колонки `deadline_at`, без удаления профилей или ответов. Для старого ожидающего вопроса, у которого дедлайн ещё не был назначен, первый запрос после обновления назначает 30 секунд.

## Адаптация и награды

Категории: программирование, математика, история, география, наука. В каждой по 18 вопросов: по шесть лёгких, средних и сложных. Новые игроки начинают со среднего уровня.

Оценка освоения категории = `(правильные + 1) / (попытки + 2)`. До четырёх ответов сложность не меняется. Далее оценка ниже 45% выбирает лёгкие вопросы, от 75% — сложные, иначе средние. Вероятность категории — 30% равномерного выбора + 70% веса `1 − оценка`. Ранее выданные вопросы исключаются из раунда. При исчерпании нужной сложности выбирается ближайшая доступная, затем другая категория. Алгоритм основан на правилах, а не на обученной модели.

Верный ответ: 10/20/30 XP. Каждые пять верных ответов подряд в одном раунде дают ещё 30 XP. Ошибка обнуляет серию, XP не отнимается. Уровень = `1 + floor(XP/100)`: Новичок, Ученик, Исследователь, Стратег, Мастер знаний, далее Легенда знаний N.

Достижения выдаются однократно. Математик и Программист требуют ≥10 ответов и ≥80% точности по категории; Эрудит — ≥70% в трёх категориях при ≥6 ответах в каждой. «Без ошибок» требует завершить все 10 вопросов без ошибок. В итогах сильными считаются категории с минимум двумя ответами и сглаженной оценкой от 60%; с оценкой ниже 50% — зоны роста. При малом числе ответов выводится просьба продолжить практику.

## Типовые ошибки

| Проблема | Решение |
| --- | --- |
| `python` открывает Microsoft Store | Установите Python с python.org; используйте `py -3` и `.venv/Scripts/python.exe` |
| `npm.ps1` запрещён политикой PowerShell | Используйте `npm.cmd`, как в инструкции |
| Не найден `py` или `node` | Переустановите с добавлением в PATH и перезапустите терминал |
| Backend недоступен / 500 от Vite | Запустите uvicorn на 127.0.0.1:8000, посмотрите его терминал |
| Порт 5173 или 8000 занят | Закройте прежний процесс сервера; Vite настроен не выбирать случайный порт |
| Камера или микрофон запрещены | Откройте настройки разрешений слева от адреса, разрешите устройство, повторите включение |
| Камера не найдена или занята | Подключите её, закройте Teams/Zoom и другие программы захвата |
| Модель не загружается | Выполните `node scripts/setup-mediapipe.mjs` в frontend; проверьте доступ к storage.googleapis.com |
| Голос не поддерживается / ошибка сети | Используйте Chrome/Edge и проверьте интернет; доступность Web Speech зависит от браузера |
| Жест не выполняется | Держите руку в кадре 0,65 с, обеспечьте освещение, проверьте уверенность; смените жест после действия |
| На другом компьютере нет старого прогресса | SQLite локальна. Перенесите battle.db при остановленном сервере |

## API и ограничения

`POST /api/players`, `GET /api/players/{id}`, `GET /api/players/{id}/stats`, `GET /api/players/{id}/achievements`; `POST /api/sessions`, `GET /api/sessions/{id}`, `POST /api/sessions/{id}/next`, `/answers`, `/finish`. Подробные схемы доступны в Swagger `/docs`.

Ответ и объяснение не включаются в выдачу нового вопроса. Сервер сверяет назначенный вопрос, считает XP и защищает повторное подтверждение уникальным ограничением и транзакцией с SQLite `BEGIN IMMEDIATE`. «Следующий вопрос» не позволяет пропустить ожидающий ответ. Завершение идемпотентно.

Это локальный университетский MVP с входом по никнейму, без паролей, токенов доступа и разграничения прав на профили. Не публикуйте backend в интернет как многопользовательский защищённый сервис. Правила адаптации не обучаются; банк статичен. Сложность содержательная, но не калибрована на большой выборке студентов. Модель жестов работает на главном потоке с ограничением примерно до 15 кадров/с; на слабом устройстве возможны задержки. История в интерфейсе ограничена 100 последними ответами, полная хранится в базе. Шрифт Manrope загружается опционально из Google Fonts, без сети используется Segoe UI. Пользовательские данные и видео не отправляются платным AI API.

## Бесплатная локальная модель (Ollama)

Для «Своей игры» добавлен независимый локальный режим: Qwen3 4B Instruct создаёт вопросы, выполняет редактуру и проверяет свободные ответы. OpenAI API не вызывается; ключ не требуется. Точные совпадения и варианты ответа по-прежнему проверяются сразу на сервере.

В `backend/.env`:
```
AI_PROVIDER=ollama
OLLAMA_MODEL=qwen3:4b-instruct
```

На этом компьютере Ollama установлена отдельно от проекта в `%LOCALAPPDATA%/Programs/AIKnowledgeBattle-Ollama`, веса — в `%USERPROFILE%/.ollama/models`. На другом компьютере сначала установите [Ollama для Windows](https://ollama.com/download/windows). Затем запустите `Start-Local-AI.ps1`; он запустит локальный сервис и при необходимости загрузит модель. Загрузка весов — около 2,5 ГБ. `Start-Backend.ps1` также запускает этот помощник при `AI_PROVIDER=ollama`. После этого запустите frontend обычным способом.

Модель работает на процессоре; 16 ГБ RAM подходит для выбранного варианта, но свободная память и другие программы влияют на скорость. Подготовка 40 вопросов может занять заметное время: экран показывает тему и этап редактуры. Вопросы создаются пакетами по пять, каждый пакет проходит редакторскую проверку и до двух исправлений; принятые темы не генерируются повторно в этой попытке. Не прошедшая проверку тема сообщает об ошибке, демо не подставляется вместо генерации.

Локальная модель слабее больших облачных моделей: возможны фактические ошибки, особенно в узких темах и мемах. Фильтры не гарантируют достоверность каждого факта. Это рабочий бесплатный режим для разработки и пробных партий, а не обещание качества GPT-5.4.

Все обращения адаптера идут только на `127.0.0.1:11434`, без прокси окружения. Автоматического перехода на OpenAI нет. Облачные теги Ollama запрещены; запускаемый проектом сервис получает `OLLAMA_NO_CLOUD=1`. Отсутствие сервиса/модели явно отображается на экране тем.

Журнал сохраняет локальные вызовы с префиксом `ollama/`, токены и нулевую стоимость API, включая неудачные попытки. Старые расходы OpenAI остаются в истории. Это учёт API, а не баланс аккаунта и не стоимость электричества. Веса, runtime, `.env` и базы данных не входят в ZIP проекта.

Для осознанного возврата к OpenAI нужно вручную изменить `AI_PROVIDER=openai`, настроить ключ и перезапустить backend; платные модели сохраняются в настройках отдельно.

Документация: [структурированный JSON Ollama](https://docs.ollama.com/capabilities/structured-outputs), [Qwen3 4B Instruct](https://ollama.com/library/qwen3:4b-instruct).


## Текущий основной режим: OpenAI

По запросу пользователя основной провайдер возвращён на `AI_PROVIDER=openai`: GPT-5.4 для генерации и редакторской проверки, GPT-5.4-mini для смысловой проверки свободных ответов. Ollama остановлена; запуск backend в этом режиме не включает локальную модель. Ключ остаётся только в `backend/.env`.

Для партий на восемь тем редактор больше не переписывает все 40 вопросов при замечаниях. Сервер сохраняет одобренные клетки, запрашивает только отклонённые и отдельно проверяет замены. Допускается до трёх адресных исправлений; неполные замены, неизвестные клетки, несовпадение заданных форматов и окончательный отказ редактора останавливают подготовку. Демо не подменяет результат AI. Прежняя совместимость с одиночными партиями на пять тем сохранена.

Сгенерированная партия хранится в локальной базе; после обновления страницы её можно продолжить через «Своя игра» → «Продолжить партию». До открытия вопроса таймер не идёт. Камера, голос, отдельные очки трёх участников и таймер 30 секунд сохранены. При переносе проекта ZIP не содержит базу с подготовленной партией, ключ и журнал расходов: они остаются на текущем компьютере.
